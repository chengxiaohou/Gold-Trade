# 回测引擎实现方案

## Context（背景与目标）

股息率一览的回测页面当前只有 UI 骨架："运行"按钮为空，图表买卖点覆盖层与成交记录表是空数据源（`demoMarkers`/`tradeRows` 均置空待填充）。本次要**实现真实回测引擎**：让用户配置的规则（触发标签 + 方向 + 仓位%）在实际历史日线 K 线上逐日扫描信号，生成买卖点、成交记录与资金统计。

项目已有一批**纯净、可复用的标签判定函数**（components/StockDividendPage.tsx 内）：`analyzeKlinePatterns`（十字星/金针探底等）、`analyzeDailySignals`（MACD/放量/缩量）、`analyzeFengSignals`（缩量入场低位/放量突破均线/缩量急拉/放量破位等），统一输入 `BollKline[]`、参数化于 `DEFAULT_TAG_PARAMS/TagParams`。回测引擎应复用它，保证信号与原页面一致。

## 技术路径

**新建共享模块 `services/tagAnalyzers.ts`**：把 3 个 analyzer + 内部 calc 纯函数 + 相关 interface（KlinePattern/DailySignal/FengHit/FengDaySignal）整体迁出并 `export`；StockDividendPage.tsx 改为从该模块 import（删除模块内定义，代码零改动、零回归）。单一事实源，买卖信号与原页面完全一致。

**新建 `services/backtestEngine.ts`**：实现逐日扫描引擎。

## 回测算法（因果、无未来函数）

数据：`res.data.klines`（BollKline[]，含 date/open/high/low/close/volume），防御性按 date 升序重排。对 `i=30..n-1` 构造滑动窗口 `win = klines.slice(0, i+1)`，分别调用：
- `analyzeKlinePatterns(win, fmt, cfg)` → 取 `date === win.last.date` 的 patterns
- `analyzeDailySignals(win, true)` → 过滤当日 signals
- `analyzeFengSignals(win, fmt, true, cfg).latest` → 当日 add/reduce

因 analyzer 内 `i = n-1` 即当日，"放量破位+2日不收复"的未来函数在严格因果窗口下天然不触发；该规则改在"确认日（d+2 收盘后）"落卖出点，保证执行时点已收盘确认。

决策模型：**单持仓**。`cash=初始资金, shares=0, avgCost=0`，每日先卖后买：
- 卖出规则仅在 `shares>0` 生效；卖 `floor(shares*pct/100/100)*100`（pct=100 全清，结算 realizedPnl 记胜）。
- 买入规则仅在 `shares===0` 生效；买 `floor((cash*pct/100)/price/100)*100`（整百股）。
- 同日多规则以 pct 最高命中；手续费默认 0（可配 feeRate）。
- 每日记权益 `cash+shares*close`，算出期末市值、总收益、胜率（平仓中盈利占比）、最大回撤、交易次数。

## 边界映射（根因）

UI 下拉标签名 与 信号函数返回名不完全一致（如 UI"缩量急拉"≠函数"无量/缩量急拉"、UI"放量破位不收复"≠函数"放量破位+2日不收复"、金针探底可能输出"放量金针"）。用 `BACKTEST_TAG_CATALOG` 目录映射稳定 key → UI 中文标签 → 来源 analyzer + signalName，不能直接字符串比对。

## 核心类型（services/backtestEngine.ts 新增）

```ts
export interface BacktestParams { feeRate?: number; lotSize?: number } // 默认 0, 100
export const BACKTEST_TAG_CATALOG: Array<{ key; label; group: BacktestTagGroup; source:'feng'|'pattern'|'daily'; signalName: string }>[]
export function runBacktest(k: BollKline[], s: BacktestStrategy, p?: BacktestParams): BacktestResult
```
复用 types.ts 已有 `BacktestRule/BacktestStrategy/BacktestTrade/BacktestResult/BacktestTagGroup`。

映射到 UI：
- `TickSpec = { id: trade.id, time: trade.date, anchorPrice: action==='buy' ? low : high }`
- 表格行 `{ time: date, action, price, shares, amount, triggerLabel: tagName }`
- 统计 = result 六项

## 状态接线（BacktestModal.tsx）

1. `useState<string[]>(['r1','r2'])` → `useState<BacktestStrategy>({ rules: [], initialCapital: 100000 })`；`initialCapital` 并入 strategy。
2. `RuleEditor`（L21、L711）加受控 props `{ value: BacktestRule; onChange }`，把 启用 / 标签 key / 方向 / 仓位% 上抛，父级更新 `strategy.rules`。
3. 数据 effect 额外存 `res.data.klines`（BollKline[]）为 `rawKlines`。
4. 新增 `const [result, setResult] = useState<BacktestResult|null>(null)`；`runBacktest` 读 rawKlines+strategy 调引擎后 setResult。
5. **运行按钮（L463）** `onClick={runBacktest}`。
6. `demoMarkers`（L305）改为由 `result.trades` 映射替换 `[]` 占位；`tradeRows`（L337）直接取 trades。
7. 统计区（L506-513）`<Stat>` 绑 result：初始资金/期末市值/总收益/胜率/最大回撤/交易次数。
